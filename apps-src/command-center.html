Monitors

Each monitor is a URL Command Center polls. It should return JSON — e.g. a small status endpoint in front of a database or service. Top-level numbers/text become metrics.

Monitors are only polled while this app is open. That button drafts a routine for the assistant, which can poll them in the background — you send it.

Settings

Everything runs on your device. Monitors are polled from this phone; nothing is sent anywhere else. A system just needs a URL (on your network or the internet) that returns JSON — add it in 🌐 Monitors.

How systems report

Command Center shows one card per system. A system's state gets in three ways:

What it's for — once anything is on the dashboard, the assistant can read it. Try asking MyLLM:
· “are any of my systems down?”
· “what changed since this morning?”
· “monitor the greenhouse at http://greenhouse.local/status”
· “if GitHub goes red, tell me” (as a routine)
Nothing here leaves the device unless a monitor's URL is remote.

The heartbeat schema (transport-agnostic — same shape however it arrives):
      
• id — unique system name
      
• status — "ok" · "warn" · "error"
      
• metrics — any key→number/text (shown as chips)
      
• errors — optional list of strings
      
The hub stamps the time it arrives.
